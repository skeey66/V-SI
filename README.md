# V-SI — 가상 SI 회사

**평소 말로 요청하면, AI 에이전트 네 팀이 순서대로 일해서 돌아가는 코드를 만들어 낸다.**

> 장바구니에 담긴 상품 금액을 모두 합치고, 합계가 5만원 이상이면 배송비 3000원을 빼주세요

이렇게 적으면 **기획 → 개발 → QA → 보안** 네 에이전트가 차례로 붙는다. 기획이
무엇을 만들지와 어떻게 확인할지를 정하고, 개발이 그 확인 항목을 통과하는 코드를
쓰고, QA가 실제로 테스트를 돌려 보고, 보안이 위험한 곳을 검사한다. QA가 반려하면
개발이 다시 만든다 — 사람이 개입하지 않아도 이 왕복이 돈다.

화면에서는 그 과정이 **3D 사무실**로 보인다. 일하는 자리는 모니터가 켜지고, 일이
넘어갈 때는 캐릭터가 자리에서 일어나 서류를 들고 걸어간다. 반려되면 빨간 서류를
들고 되돌아온다.

## 이 프로젝트가 다루는 것

에이전트에게 코드를 시키는 것 자체는 어렵지 않다. 어려운 것은 **여러 에이전트가
프로세스 경계를 넘어 협업할 때 생기는 문제들**이다 — 누가 판정하는가, 실패하면
어디서 이어받는가, 무한히 고치는 것을 어떻게 멈추는가, 사람은 언제 불러야 하는가.

이 저장소는 그 질문들에 코드로 답한 결과다.

**판정은 모델이 내리지 않는다.** PASS/FAIL 은 `pytest` 와 `bandit` 의 종료 코드가
정하고, 모델은 그것을 개발이 고칠 수 있는 문장으로 옮긴다. "통과했다고 생각한다"
는 통과가 아니다.

**목표가 비면 시작하지 않는다.** 기획이 쓴 확인 항목을 구현이 없는 상태에서
돌려 본다. 쓸 만한 테스트는 반드시 실패한다 — 부를 함수가 없으니까. 통과해
버리면 그 테스트는 아무것도 검사하지 않는다는 뜻이고, 그대로 개발을 보내면
무엇을 만들어도 통과한다. 그럴 때는 멈춰서 사람을 부른다.

**LLM 이 쓴 코드는 인터넷에 닿지 못한다.** 실행은 `internal: true` 네트워크의
전용 컨테이너에서만 일어난다. 도구도 역할마다 다르게 마운트돼서, 개발 에이전트
에게는 `run_tests` 라는 도구가 **존재하지 않는다** — 권한 표에 적어 두는 것이
아니라 서버 인스턴스를 나눠 구조로 막는다.

**죽어도 이어받는다.** 오케스트레이터를 임의 시점에 SIGKILL 해도 재기동만으로
끝까지 간다. 진행 상태는 전부 DB 에 있고, 리컨실러가 관측해 빠진 것을 다시 보낸다.

## 빠르게 돌려 보기

로컬 Ollama 가 필요하다. 비용은 0원이다.

```bash
ollama serve &
ollama pull qwen3:8b

cp .env.example .env
VSI_AGENT_MODE=llm docker compose up -d --build
```

`http://localhost:5173` 을 열고 **새 요청**에 하고 싶은 말을 적으면 된다.

로컬 모델이라 요구사항 하나에 **10~20분** 걸린다(실측: 20 tok/s). 그동안 사무실
탭에서 어느 팀이 일하는 중인지, 몇 번째 되돌려 고치는 중인지 보인다. 끝나면
**결과물** 탭에서 만들어진 파일 전체와 검사 결과를 읽고 `.zip` 으로 받을 수 있다.

### LLM 없이 구조만 보기

기본 모드는 **스텁**이다. `VSI_AGENT_MODE` 를 주지 않으면 에이전트가 LLM 을 한
번도 부르지 않고 대본대로 움직인다 — 워크플로·복구·환류가 **1초 안에** 전부 돈다.

```bash
docker compose up -d --build
./scripts/demo.sh    # 환류 2회를 거쳐 accepted 까지 완주한다
```

## 화면

| 탭 | 무엇을 보여 주나 |
|---|---|
| **사무실** | 지금 벌어지는 일. 에이전트가 일하고, 걸어가서 넘기고, 막히면 손을 든다 |
| **결과물** | 무엇이 남았는가. 만들어진 파일 전문, 검사 결과, 몇 번 고쳤는지 |
| **그래프** | 노드·이벤트 로그. 디버깅용 |

사무실의 캐릭터를 클릭하면 그 팀이 낸 산출물이 열린다. 진행 표시줄은 어느 탭에
있든 보이고, 진행 중이면 경과 시간이 올라간다.

### 사람을 부르는 두 가지

| 상태 | 언제 | 그 다음 |
|---|---|---|
| **확인해 주세요** | 기획 직후, 일을 시작하기 전 | 버튼 하나 누르면 **개발부터 이어진다** |
| **도와주세요** | 세 번 고쳐 봤지만 끝내지 못했을 때 | 끝난 상태 — 사람이 직접 손봐야 한다 |

앞의 것은 30초면 끝나고 버려지는 시간이 없다. 뒤의 것은 이미 시간을 다 쓴 뒤다.
그래서 같은 색으로 그리지 않는다.

## 구조

```
packages/          여러 컨테이너가 공유하는 라이브러리
  orchestrator/      워크플로 엔진 · 상태 기계 · 리컨실러 · HTTP API
  llm_agent/         에이전트 루프 — 도구 호출, 예산, 판정 수집
  stub_agent/        LLM 없이 대본대로 움직이는 에이전트
  agent_entry/       에이전트 프로세스 진입점 (역할은 환경변수로)
  agent_runtime/     추적(OpenTelemetry) 공통

services/          각자 컨테이너로 뜨는 것
  tool_server/       MCP 도구 서버 — 역할별로 다른 도구를 마운트한다
  event_gateway/     DB 아웃박스 → WebSocket 중계

web/               React + three.js 화면
tests/             단위 · 통합 · 수용
scenarios/         스텁 에이전트 대본 (환류 2회, 크래시 주입 등)
docs/specs/        왜 이렇게 설계했는가 — 코드 주석이 이 문서를 참조한다
docs/decisions/    구현하면서 뒤집은 판단과 그 대가
```

에이전트 넷은 **같은 이미지**를 쓰고 `VSI_AGENT` 환경변수로 역할이 갈린다. 역할이
다르면 프롬프트가 다르고, 붙는 MCP 경로가 다르고, 그래서 쓸 수 있는 도구가 다르다.

## 창구

| | 주소 |
|---|---|
| 화면 | http://localhost:5173 |
| 오케스트레이터 API | http://localhost:8000 |
| 이벤트 스트림 | `ws://localhost:8100/ws` |
| 추적 (Jaeger) | http://localhost:16686 |
| DB | `postgresql://vsi:vsi@localhost:55432/vsi` |

에이전트 넷은 `8001`(기획) `8002`(개발) `8003`(QA) `8004`(보안)로 열려 있다 —
A2A 카드는 `/.well-known/agent-card.json` 에서 볼 수 있다.

API 로 직접 넣으려면:

```bash
curl -X POST localhost:8000/requirements -H 'content-type: application/json' \
  -d '{"requirement_id":"REQ-001","title":"회원가입","run_id":"run-1"}'

curl localhost:8000/requirements/REQ-001                    # 진행 상태 + 회차 이력
curl localhost:8000/requirements/REQ-001/artifacts          # 산출물 목록
curl -X POST localhost:8000/requirements/REQ-001/approve    # 기획 게이트 승인
```

## 테스트

```bash
pip install -e ".[dev]"
pytest tests -q --ignore=tests/integration   # 286개 — 스택 없이 돈다
pytest tests/integration -q                  # 50개 — 스택이 떠 있어야 한다

cd web && npm install && npx vitest run      # 63개
```

통합 시험은 실제 컨테이너를 상대로 돈다 — A2A 제출, 푸시 콜백, DB, 오케스트레이터
SIGKILL 후 복구까지. 실제 모델을 쓰는 시험은 기본적으로 제외돼 있다(`-m llm`).

## 지금의 한계

솔직하게 적어 둔다.

**요청이 크면 못 끝낸다.** "회의실 예약 사이트를 만들어줘" 는 1시간 18분을 쓰고
포기했다. 에이전트 하나가 한 작업에 쓸 수 있는 예산이 600초인데, 로컬 8B 모델의
생성 속도(20 tok/s)로는 그 규모가 들어가지 않는다. 기획은 요구사항을 제대로
쪼갰고 — DB 스키마까지 뽑았다 — 개발이 예산에서 죽었다.

**보안 검사가 사실상 아무것도 못 찾는다.** `bandit` 은 파이썬 취약점 패턴을 보는데
만들어지는 것이 함수 몇 개라 찾을 것이 없다. 실제 실행에서 한 번도 문제를 잡지
못했다.

**"과하게 빡빡한 테스트" 는 게이트가 못 잡는다.** 기획이 `<strong>Phone:</strong>`
이라는 정확한 문자열을 요구해서 개발이 한 번 반려당한 적이 있다. 사람이 봤으면
통과시켰을 차이다. 게이트는 "아무것도 검사하지 않는" 쪽만 막는다.

**웹 페이지는 구조만 검사한다.** HTML 파일은 만들어지지만 아무도 렌더링을 보지
않는다. `<h1>` 이 있는지는 확인해도 보기에 괜찮은지는 확인하지 못한다.

**API 에 인증이 없다.** 화면은 Vite 프록시를 통해 같은 출처로만 접근하지만, 경로
자체는 열려 있다. 로컬 개발 환경을 전제로 한 구성이다.
