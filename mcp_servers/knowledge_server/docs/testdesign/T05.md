# 형식 검증 (이메일·전화번호·아이디)

## 언제
문자열이 정해진 형식인지 True/False 로 판단하는 요구사항.

## 반드시 넣을 테스트
정상 예 2개 이상, 그리고 비정상 변형을 하나씩: 구분자 없음(@ 없음), 구분자 두 개, 앞부분 빈 값, 뒷부분 빈 값, 점 연속(`a@b..com`), 최상위 도메인 한 글자, 공백 포함.

## 자주 놓치는 것
비정상 케이스를 하나만 넣는 것. 변형마다 하나씩 따로 검사해야 구현의 빈틈이 드러난다.
